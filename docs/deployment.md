# Deployment

[Deutsch](deployment.de.md) · [README](../README.md) · [Usage](usage.md) · [Backups](backups.md)

Copy [compose.yaml](../compose.yaml) and create a private `.env` beside it as shown
in the [quick start](../README.md#quick-start). The same commands work in Linux/macOS
shells and PowerShell. A release installation needs Docker with Compose; it does
not need Git or Node.js on the host.

## Configuration

Required values in `.env`:

| Variable         | Purpose                                                                                    |
| ---------------- | ------------------------------------------------------------------------------------------ |
| `ORIGIN`         | The browser URL, e.g. `http://localhost:3000` or `https://totally.example.org`             |
| `PASSWORD_HASH`  | The scrypt hash generated by setup; not the login password itself                          |
| `SESSION_SECRET` | A random session-signing secret, at least 32 characters; setup generates 64 hex characters |

Generate the login password and configuration values with:

```sh
docker run --rm ghcr.io/kingtiki/totally:latest node scripts/setup.mjs --stdout
```

The command prints configuration to stdout and the password to stderr; it does not
write a file. Copy the generated hash and secret into your private `.env` and keep
the displayed password. These instructions need no shell-specific file redirection.

Optional settings are listed in [`.env.example`](../.env.example):

| Variable          | Purpose                                                        | Default               |
| ----------------- | -------------------------------------------------------------- | --------------------- |
| `BIND_ADDRESS`    | Host interface for the published port                          | `127.0.0.1`           |
| `APP_PORT`        | Host HTTP port; also adjust `ORIGIN` when changing it          | `3000`                |
| `BODY_SIZE_LIMIT` | Maximum HTTP request size, including uploads                   | `110M`                |
| `COOKIE_SECURE`   | Optional secure-cookie setting; HTTPS automatically enables it | Derived from `ORIGIN` |
| `SMTP_*`          | Existing SMTP account for optional email                       | Disabled              |

Compose fixes `HOST=0.0.0.0`, `PORT=3000` and `DATA_DIR=/app/data` inside the
container. In a native Node.js installation, those variables can be configured
directly. After changes to `.env`, run `docker compose up -d` to recreate the container.

The app runs as user `node` (UID 1000). Data lives in the named `totally-data`
volume, prefixed by Compose's project name. Keep the installation directory/project
name and back up both the volume contents and `.env`. `docker compose down -v`
deletes the volume. For an existing installation using a host bind mount, keep
that original mount in `volumes` (e.g. `./totally-data:/app/data`); a new named
volume does not import the host folder. A host folder must be writable by UID 1000.

**Run only one process/container per data directory.** Use a local filesystem with
atomic rename support. The same Node process runs the reminder scheduler;
`/healthz` exposes only operational status.

## HTTPS and reverse proxy

Use an existing reverse proxy for TLS. In `.env`:

```dotenv
ORIGIN=https://totally.example.org
COOKIE_SECURE=true
```

`ORIGIN` must exactly match the browser URL: scheme, host and optional port, without
a path or trailing slash. Path prefixes such as `/crm` are unsupported. Forward to
the app port and allow uploads of at least 110 MB. The app uses the configured
origin rather than trusting arbitrary forwarded headers.

Example for an existing Caddy on the same host:

```caddyfile
totally.example.org {
    reverse_proxy 127.0.0.1:3000
}
```

A proxy in another container needs a shared network or a reachable app port;
its `127.0.0.1` is not the Docker host.

## Optional email

Configure an existing SMTP service in `.env`:

```dotenv
SMTP_HOST=smtp.example.org
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=your-username
SMTP_PASSWORD=your-app-password
SMTP_FROM=totally@example.org
SMTP_TO=you@example.org
```

Port 587 requires STARTTLS. For direct TLS, normally use port 465 and
`SMTP_SECURE=true`. Certificates are verified. Username/password may be empty
for an authentication-free TLS relay. Quote special characters and spaces in
`.env`, for example `SMTP_PASSWORD="my value"`.

```sh
docker compose up -d --force-recreate app
```

Then enable email in **Settings**. The default daily time is 09:00, Europe/Berlin;
both time and IANA time zone are configurable. Without SMTP, email stays disabled
and the rest of the app works normally.

- The scheduler checks every minute and at startup; no open browser is needed.
- A digest contains today's birthdays and active due/overdue follow-ups. Empty digests are not sent. At most one successful email digest is generated per local calendar day.
- A restart after the scheduled time catches up today's digest. Pending/failed deliveries survive restarts. Days when the app was completely offline are not backfilled.
- Failed deliveries retry after 5, 10, 20, etc. minutes, capped at 6 hours. Settings shows recent results and offers a manual check.
- An already generated failed email keeps its original content, even if reminders are changed or completed later. New items after a successful daily digest wait for the next one; birthdays only count on their day.
- A crash after SMTP acceptance but before saving success can cause duplicate email.
- **Done** completes a one-off follow-up or the current annual occurrence; for a contact schedule it starts a new interval today. Only **Log contact** records actual contact and recalculates schedules from the latest contact.
- Birthdays can omit the year; February 29 is observed on February 28 in non-leap years.

See [usage](usage.md#push-on-phones-and-computers) for Web Push.

## Build from source

For development, local modifications or before the first release, obtain the
repository and build a local image:

```sh
docker build -t totally:local .
```

Set `image: totally:local` in the same [compose.yaml](../compose.yaml). Generate
credentials using `totally:local` in the setup command above, or keep your existing
`.env`. Start with `docker compose up -d --pull never`. No additional Compose file
is needed; the same data volume is used.

## Updates

Make a [full backup](backups.md) first. For release images, change the `image:`
tag in `compose.yaml` to the desired published version (or keep `:latest`), then:

```sh
docker compose pull
docker compose up -d
docker compose logs --tail=100 app
```

For a local build, update the checkout, rebuild `totally:local` and run
`docker compose up -d --pull never`. Older versions may reject newer data fields;
keep a matching backup for rollback.

## Prebuilt release images

[CI](../.github/workflows/ci.yml) builds and publishes a **Linux amd64** image only
when a GitHub Release is published and verification succeeds. Pushes, PRs, drafts
and manual CI runs do not build or publish images.

The image name is derived from the lowercase GitHub owner/repository, currently
`ghcr.io/kingtiki/totally`. A release tagged `v1.2.3` publishes `:v1.2.3` and
`:latest`. A prerelease such as `v1.3.0-rc.1` publishes only its exact tag.
Every stable release updates `latest`, including older versions. Prefer a version
tag or digest for pinned deployments. See the [release rules](../CONTRIBUTING.md#pull-requests-and-releases).

Private GHCR packages need authentication; the maintainer must make the package
public for anonymous pulls. A public repository alone does not guarantee public
package visibility.

## Troubleshooting

- **403 / Cross-site POST:** match `ORIGIN` exactly to the browser URL. `localhost`, `127.0.0.1` and LAN hostnames differ. Recreate the container after changes.
- **HTTP login fails:** use `COOKIE_SECURE=false` for local HTTP testing, `true` for HTTPS.
- **Data directory not writable:** check ownership and permissions for UID 1000.
- **Photo import fails:** use a complete ZIP with `data.json` and matching images; see [backups](backups.md).
- **No push message:** check HTTPS, device permission and a [test notification](usage.md#push-on-phones-and-computers).

Logs: `docker compose logs --tail=100 app`. Remove credentials and private contact
data before sharing logs.
